# Customer-Owned Web Presence — Product-Led Growth and Quality Strategy

## Positioning: make customer control tangible
**One-line promise:** You are in control of your web presence and your data.

**Differentiator:** Premium, fully modular personal website studio with portable profiles, independent hosting, backups and a planned Auto-Regenerative Presence Engine. Customers should be able to keep their identity through provider disruptions without depending on a single vendor. This is a **recovery-first goal**, not an uninterrupted-availability guarantee.

### Value ladder
1. Free demo: switch themes, edit a fictional profile, import/export manual JSON backups; no payment or account required.
2. Starter product (planned): personal site generator, reusable templates, exportable static builds, local backups and guided deployment.
3. Resilience product (planned): provider connectors, domain/DNS monitoring, automatic encrypted multi-location backup, integrity checks, staged restore and emergency switchovers.
4. Managed product (planned): customer authentication, configuration auditing, monitored deployments, policy-based alerts, tested backups and governed failover.

Never describe levels 2–4 as released before independent testing and commercial readiness.

## Product-led activation
- Entry CTA: **Try the studio → edit a name → switch theme → download my site backup**.
- No forced signup before the first successful edit/export. Preserve user changes across language and theme switching.
- Make actions on the landing page lead to the real editor rather than a fake animation.
- Default all exports to transparent, documented, portable formats.
- Ask for optional feedback after successful export; never fabricate five-star reviews or endorsements.

## Repeatable distribution experiments
| Acquisition route | Test | Measurement |
|---|---|---|
| Search | Detailed tutorials for changing DNS, moving hosts, backing up personal sites and recovering outages | Organic qualified visits and task completion |
| AI-assisted discovery | Clear indexable docs, factual comparisons, structured examples, concise FAQs | Referral traffic and direct user citations where measurable |
| Community | Open-source sample themes, honest Dev.to/Reddit/Hacker News demonstrations with useful technical insights | Relevant click-through, substantive replies |
| Templates | Free audience-specific portfolios: student, creator, engineer, researcher | Template preview → first edit → export |
| Sharing | Optional attribution to the editor and portable shared public templates | Consented referral installs/activations |
| Marketplace | Review eligible directories, storefronts and app marketplaces only for products that meet their packaging and policy rules | Qualified installs, verified sales, refund rate |
| Customers | Interview early adopters after a successful real publish and restore | Reported usability, renewal, recovery success |

Do not spam forums, buy reviews, manufacture statistics, or market untested recovery features as delivered.

## Quality and performance gates
- Test portrait/scene center geometry and cropping on all themes at 390px, 768px, and 1280px.
- Test all supported locale controls and RTL Arabic, including returning to English without data loss.
- Maintain keyboard focus, reduced-motion support, contrast and responsive layout tests. Audit to WCAG 2.2.
- Audit Core Web Vitals: LCP, INP, CLS, and repeat on real mobile devices and representative network conditions.
- Capture actual build screenshots for every layout and viewport and review visual diff artifacts.
- Treat any broken import/export or lost local data as a release blocker.
- Browser-local manual export is not equivalent to an automatic backup. Only claim verified RPO, RTO and uptime after independent failure-injection testing.

## SEO and platform boundaries
The GitHub Pages demo is currently marked `noindex,nofollow` and disallowed in `robots.txt`. That is appropriate for a fictional product prototype, but **cannot itself be an organic-search acquisition channel**. Create a separate customer-facing documentation/marketing site with indexable, original content on permitted commercial hosting when ready. Keep the source demo separate.

Follow Google's people-first SEO guidance, not keyword stuffing or mass-generated thin pages. Document real, original results of deployment/restore tutorials and technical comparisons. Verify performance with Chrome tooling and field measurements, and avoid claiming higher search rankings.

GitHub Pages is not permitted as the primary host of an e-commerce / SaaS business. Commercial payment must run on an independently approved host, with verified merchant account and backend fulfillment.

## Data to measure without covert tracking
- Aggregate visits and first-editor-open rate using opt-in privacy-preserving analytics on the future commercial host.
- Funnel steps: first edit, first export, template change, first successful independent deployment, first verified restore, paid conversion, support resolution.
- Reliability metrics: independent probe uptime, backup age, verified restore success, recovery latency and loss of customer data.
- Customer value: sustained 30/90 day usage and voluntary ratings from actual paying/using customers.
